Follow a distributed execution

Write a YAML workflow with a required readable name and inputs referencing upstream task ports. Submit it together with optional YAML execution-policy and variable files. Union dispatches YAML subjobs with local connections as task:port and remote inputs as locations containing origin, task, port and producer_identity. Only remote output readers need output_routes with consumer_identity. Stream representations come from stream headers.

Inspect the node topology and complete Sub-job definition, then expand Operator step records for individual states and durations. Jobs have generated execution IDs and readable names shared by global jobs and their subjobs. Execution history is separate from output materialization: retained job metadata does not imply saved result payloads.
