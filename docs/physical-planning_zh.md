# 物理计划生成与优化

Union 负责选择任务在哪里执行，XStream 执行各成员的本地子任务。在 Union 看板中打开**物理计划 → 完整计划**，可以查看规划摘要、预计传输、runtime 候选和节点选择理由；执行信息展示实际启动的执行单元。Designer 负责设计 Job，不选择分布式执行计划。

```mermaid
flowchart LR
    J[提交的逻辑计划] --> N[解析成员命名空间]
    N --> M[采集有界元数据]
    M --> C[展开候选节点分配]
    C --> V[检查硬约束]
    V --> E[估算整个计划成本]
    E --> B[保留有限个最佳候选]
    B --> P[选定物理计划]
    P --> R[成员验证并启动执行单元]
```

## 规划快照

快照包含已批准成员、容量、已安装 executor 标识、内存观测、已保留步骤数量、可获取的 Item 大小，以及已安装算子的 runtime／依赖元数据。Union context Item 和完整成员 DACP URI 均参与来源大小估算。数据所有者是已批准成员时，读取步骤固定在该节点。外部 URI 保持远程读取，不会自动将外部服务器加入执行成员。

元数据请求使用已有认证成员连接、证书绑定及有界 RPC 超时。算子画像只读取本地清单／缓存，不执行算子、不下载程序包、不加载 runtime 镜像。画像缺失时不声称 runtime 兼容；大小缺失时采用保守估算，并记录规划提示。元数据可能触发格式正常的有界 schema 推导，但规划不会请求完整记录计数或全量扫描输入。大小或画像查询不授予读取权限；执行前仍检查数据集发布策略和成员准入。

## 候选选择

规划器按依赖顺序展开合法节点，每一步最多保留 `beam_width` 个部分候选。这是有界束搜索，不是穷举，也不保证全局最优。每个候选按整张图估算，因此后续汇合或固定位置步骤会影响前面计算的放置选择。评分相同时依次优先跨节点传输量较少、进程较少以及确定性的节点顺序。

硬约束包括已批准成员、数据所有权、显式节点分配、节点及 Union 任务容量、已知 executor 支持，以及同时具有内存估算和空闲内存观测时的估算内存限制。runtime／环境兼容性决定合并候选。成员准备执行时再次检查权限、环境和资源；估算不等于资源预留。已有任务产生保守的排队成本，而不是排除所有当前繁忙节点。

## 执行单元与传输

已安装 runtime 镜像、依赖环境和 executor 配置相同时，可以识别**进程合并候选**。仅当整个成员分区收缩后无环、且不存在物化／重放或被选为输出的读取步骤等边界时，才估算为可合并。成员准备阶段仍要求 executor 接受该组。看板区分候选和实际共享进程，准备时也可能改为独立执行单元。

连线区分 `arrow_in_process_candidate`、同节点 `arrow_ipc` 和跨节点 `arrow_flight`。流式传输可与上游计算重叠，成本模型沿依赖关键路径计算，不累加所有并行分支。估算包含启动、计算、链路延迟／带宽和排队成本。这是启发式模型，不是完整调度器仿真。输出大小默认采用上游输出估算之和，并不意味着任意算子都保持数据量不变。

默认成本是保守假设，不是实测成绩：未知来源 1 MiB、非读取步骤计算 100 ms、启动 500 ms、跨节点吞吐 100 MB/s 且延迟 2 ms、本地吞吐 1 GB/s 且延迟 0.1 ms。`item_source` 是宿主流来源，不计算子进程启动成本。SQL、选择条件或不同表示改变输出流时，源文件大小仅是输出大小的近似。

## 配置

配置在 **Union 启动 YAML** 中，不在 Job 中：

```yaml
planning:
  provider: cost
  beam_width: 32
  settings:
    unknown_bytes: 1048576
    compute_ms: 100
    startup_ms: 500
    network_bytes_per_second: 100000000
    network_latency_ms: 2
    local_bytes_per_second: 1000000000
    local_latency_ms: 0.1
```

束宽为 1–256。成本值必须有限且非负，带宽必须大于零，未知配置会被拒绝。更大的束宽比较更多方案，也增加规划开销。插件配置由管理员控制，Job 不能加载优化代码。

看板／历史中的 `planning` 字段记录 provider、搜索宽度、候选评估次数、选定评分、预计完成时间、跨节点字节数、进程数、逐步骤估算、执行单元候选、连线及提示。估算有明确标注，与实际流量、实际执行单元分开。历史重放保持保存的位置与物化边界，不会静默替换为新优化计划。

## 已实现范围

规划器结合数据本地性、有界整图成本比较和潜在进程合并选择位置，保留提交的步骤图和显式执行策略。不自动前移过滤、不重写 Join、不通过算子名猜测语义、不自动引入物化，也不对运行中的 Job 重规划。这些变化需要明确的语义契约和进一步验证。安装优化插件可以在不改变逻辑图的情况下提供领域数据量／耗时估算、链路成本、额外节点分配候选及评分。
